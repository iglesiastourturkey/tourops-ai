Implement only Sprint 3.1: Accounting UX fixes and operational finance enhancements.

Current UI problems:
- Primary buttons such as “Yeni İşlem”, “Raporlar & İhracat” and dialog confirmation buttons have insufficient contrast and appear disabled even when active.
- Icon-only accounting actions are unclear.
- English category values such as “other” are visible.
- The account page displays an incorrect generic role label such as “Personel”.
- Accounting statistics do not yet provide enough cash-flow, tax and payment information.

1. Button visibility and states

Fix all accounting buttons so their states are visually clear:

- Active primary button:
  teal background
  white text
  visible border
  proper hover and focus state

- Disabled button:
  muted gray background
  muted text
  not-allowed cursor

- Destructive button:
  red text or red background according to context

Apply this to:
- Yeni İşlem
- Raporlar & İhracat
- Onayla
- Reddet
- Eksik Bilgi
- Kaydet
- PDF / Excel / ZIP export buttons

Never use white text on a nearly white background.

2. Tooltips and accessible labels

Every icon-only action must have:
- Turkish tooltip on hover
- accessible aria-label
- visible focus state

Required tooltips:

Green check:
“İşlemi onayla”

Red cross:
“İşlemi reddet”

Warning/info action:
“Eksik bilgi olarak işaretle”

Plus icon:
“Yeni gelir veya gider işlemi oluştur”

Refresh:
“Verileri yenile”

Arrow on cards:
“Detayları görüntüle”

Export icon:
“PDF, Excel veya ZIP olarak dışa aktar”

On mobile, do not rely only on hover. Use visible text labels or an action menu.

3. Replace ambiguous icon actions

In accounting tables, replace isolated icons with a three-dot action menu or clearly labelled buttons:

- Detayları Gör
- Düzenle
- Onayla
- Reddet
- Eksik Bilgi
- Ödendi İşaretle
- İptal Et

Approved transactions must not be hard-deleted.

4. Turkish labels

Map all internal values to Turkish UI labels.

Examples:
- other → Diğer
- income → Gelir
- expense → Gider
- pending → Bekliyor
- paid → Ödendi
- partially_paid → Kısmen Ödendi
- pending_review → İnceleme Bekliyor
- approved → Onaylandı
- rejected → Reddedildi
- missing_information → Eksik Bilgi

Never expose raw database enum values in the UI.

5. Fix account role label

The account/settings page must display the actual profile role:

- super_admin → Süper Yönetici
- admin → Yönetici
- operations → Operasyon
- accounting → Muhasebe
- guide → Rehber

Do not show the generic “Personel” label when a real role exists.

7. Tax and VAT support

This is an operational accounting aid, not an official tax filing system.

Add configurable tax settings under:
Ayarlar → Muhasebe Ayarları

Fields:
- Default VAT rates
- Active/inactive VAT rates
- Default currency
- Fiscal year start month
- Payment methods
- Income categories
- Expense categories
- Document numbering preferences
- Accountant notes

Do not hardcode Turkish legislation.

For each transaction support:
- VAT-inclusive or VAT-exclusive amount
- VAT rate
- net amount
- VAT amount
- gross amount

Calculated values must remain editable before approval.

Show a disclaimer:
“Bu ekran operasyonel finans takibi içindir; resmi muhasebe ve vergi beyannamesi yerine geçmez.”
