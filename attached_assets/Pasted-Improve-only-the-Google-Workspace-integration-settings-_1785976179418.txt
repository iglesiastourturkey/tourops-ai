3. OAuth behavior

Prefer one shared Google connection record but track Gmail and Drive grants separately.

Do not request unnecessary scopes.

Gmail:
- read-only message access
- label/search access

Google Drive:
- prefer file-specific access where possible
- do not request unrestricted full Drive access unless absolutely required
- clearly report the exact scopes used

If the same Google account is already connected:
- allow adding the missing Gmail or Drive scope without creating a duplicate connection
- preserve the existing refresh token safely
- update granted scope metadata

4. Connect/disconnect behavior

Connect buttons:
- start backend OAuth flow
- return to the Google Workspace settings page
- show success or failure toast
- refresh connection state

Disconnect:
- require confirmation dialog
- revoke or remove only the selected integration grant where technically possible
- if Google only supports revoking the entire token, explain this clearly in the UI before disconnecting
- do not delete imported emails, created operations, or previously indexed Drive files

5. Configuration-not-ready state

If Google OAuth environment variables are missing:
- keep the warning
- disable connect buttons
- show exactly which configuration is missing using safe variable names only
- never display client secrets

Expected safe configuration names may include:
- GOOGLE_CLIENT_ID
- GOOGLE_CLIENT_SECRET
- GOOGLE_REDIRECT_URI
- GOOGLE_GMAIL_REDIRECT_URI
- GOOGLE_DRIVE_REDIRECT_URI

Use only the variables actually required by the implementation.
