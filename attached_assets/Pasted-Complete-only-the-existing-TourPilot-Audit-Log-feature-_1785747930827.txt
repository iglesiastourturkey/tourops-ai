Complete only the existing TourPilot Audit Log feature.

Important:
- Reuse the existing audit_logs table.
- Reuse the existing /api/audit route if present.
- Do not create a duplicate audit table or parallel logging system.

Goal:
Provide a production-ready Audit Log page for super_admin users and record critical actions across TourPilot.

3. Events to record

Record only important actions:

Authentication:
- login success
- login failure where available
- logout
- password reset requested
- password changed

Users and authorization:
- invitation sent
- user activated/deactivated
- role changed
- permissions changed
- username changed
- temporary password generated
- sessions revoked

System:
- system mode changed
- maintenance settings changed

Operations:
- operation created/updated
- status changed
- guide assignment changed
- driver/vehicle assignment changed
- task created/completed/reopened/deleted
- incident created/resolved

Accounting:
- accounting document approved/rejected
- transaction created/deleted
- approved financial records changed

Do not log read-only page views or every GET request.

4. Audit record structure

Reuse existing columns where possible.

Each event should contain:
- actorProfileId
- actor email/name snapshot
- actor role
- action
- module
- entityType
- entityId
- result
- description
- ipAddress
- userAgent
- metadata JSON
- createdAt

Metadata must contain only relevant changed fields.
Never store passwords, JWTs, API keys, cookies or uploaded file contents.

- capture IP using trusted proxy settings correctly
- sanitize metadata
- enforce super_admin permission on GET /api/audit

Add only the endpoints needed for:
- paginated audit list
- filter options if required
- single audit detail if required

For now:

- do not add automatic deletion
- document a future retention recommendation
- audit records must not be editable from the UI
- do not add delete buttons
